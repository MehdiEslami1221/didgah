# Didgah

![Didgah — Urban research surveys, illustrated with a green city skyline](docs/images/didgah-cover.webp)

A Persian research survey platform built with Next.js, TypeScript and SQLite. Didgah collects complete questionnaires, gives the researcher a private dashboard, and produces individual and aggregate PDF reports.

The included questionnaire examines the direct influence between eight factors in urban investment policy implementation and sustainable development. It contains 56 questions, arranged in eight sections of seven questions each.

## Features

- Persian, right-to-left interface with locally served Vazirmatn fonts.
- Required first and last names; optional phone number and professional background.
- Section-by-section questionnaire with progress tracking and a final review.
- Browser-local draft recovery and server-side validation of all 56 answers.
- SQLite persistence with WAL mode and idempotent submission retries.
- Password-protected administration with signed, eight-hour HttpOnly sessions.
- Response search, individual answer review and deletion with confirmation.
- Answer distributions, per-question averages, section summaries and an 8×8 direct-influence matrix.
- Downloadable summary, individual and combined PDFs, plus browser printing.
- Database backup command and deployment examples for Nginx and systemd.

## Run locally

Use Node.js 22 or 24 LTS and npm.

```bash
git clone https://github.com/MehdiEslami1221/didgah.git
cd didgah
npm ci
npm run setup
npm run pdf:install
npm run dev
```

Open `http://localhost:3000`. Administration is available at `http://localhost:3000/admin`.

The local default credentials are **admin / admin**. Change them in `.env.local` before exposing the application to the internet. `npm run setup` generates a random session secret and preserves an existing environment file.

On Windows, `start-windows.bat` performs the initial installation and opens the application. Keep its terminal window open while using the development server.

For a production build:

```bash
npm run build
npm start
```

## Configuration

See [`.env.example`](.env.example) for available settings. Keep actual credentials in `.env.local`; do not commit that file.

| Variable | Purpose |
| --- | --- |
| `ADMIN_USERNAME` | Administrator login name; defaults to `admin`. |
| `ADMIN_PASSWORD` | Administrator password; defaults to `admin` for local use. |
| `SESSION_SECRET` | Signing key generated by the setup command. Rotating it invalidates existing sessions. |
| `DATABASE_PATH` | SQLite file path; defaults to `./data/survey.sqlite`. |
| `APP_ORIGIN` | Public origin, such as `https://survey.example.com`, without a trailing slash. |
| `COOKIE_SECURE` | Set to `true` when serving over HTTPS; use `false` for local HTTP. |
| `CHROMIUM_PATH` | Optional absolute path to a compatible Chromium executable for PDF rendering. |

Changes to environment settings require an application restart. They do not require rebuilding the application.

## Deploy and maintain

[Deployment guide](docs/deployment.md) covers Ubuntu, Nginx, HTTPS, systemd, upgrades and migration to another server.

[PDF troubleshooting](docs/pdf-troubleshooting.md) covers browser installation, custom executable paths and downloads blocked by the browser provider.

[Data and reporting](docs/data-and-reporting.md) explains scoring, privacy, backups and deletion behavior.

This application needs a persistent Node.js process and a writable disk. It cannot run on GitHub Pages or other static-only hosting. Run one application instance against a local SQLite file.

## Validation

```bash
npm test
npm run build
npm run typecheck
npm run test:pdf
```

The automated tests cover questionnaire structure, validation, SQLite persistence and deletion, duplicate request handling, authentication, origin checks, report escaping and statistical calculations. The PDF smoke test renders all three report formats using synthetic data without creating questionnaire responses.

CI runs the tests, production build and PDF smoke test on Ubuntu with Node.js 24. Check the workflow result for the current commit rather than treating the presence of a workflow as a passing result.

## Project layout

```text
app/             Pages and HTTP route handlers
components/      Questionnaire, login and research dashboard
lib/             Survey content, validation, storage, sessions and reports
scripts/         Setup, development runner, backup and PDF smoke test
tests/           Data, validation and route tests
deploy/          Nginx and systemd examples
docs/            Deployment, reporting and troubleshooting guides
public/fonts/    Embedded report font and its license
```

The bundled questionnaire is fixed in [`lib/survey.json`](lib/survey.json). It is not a form builder. If you change questions or scoring after collecting responses, use a new database to avoid mixing incompatible datasets.

## Reporting scope

Options are coded from 0 (no influence) to 4 (very high influence). Reports show descriptive counts, percentages and means. The matrix contains raw mean direct-influence ratings; it is **not a completed DEMATEL analysis**, and there are no right answers or pass/fail scores.
