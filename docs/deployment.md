# Deploying on Ubuntu

These instructions assume a dedicated application directory at `/opt/urban-survey`, a service account named `survey`, and the public hostname `survey.example.com`. Replace that hostname with your own. The repository is named Didgah; the service and directory retain the `urban-survey` name so existing installations can be upgraded without renaming their data paths.

Use Node.js 22 or 24 LTS, npm and an Ubuntu release supported by your installed Playwright version. Ensure ports 80 and 443 are reachable. If another web server is already installed, integrate the virtual host into the existing configuration instead of replacing it.

## 1. Install the source

Run system administration commands as root or prefix them with `sudo`.

```bash
apt-get update
apt-get install -y git nginx certbot python3-certbot-nginx build-essential python3
useradd --system --create-home --home-dir /home/survey --shell /bin/bash survey
git clone https://github.com/MehdiEslami1221/didgah.git /opt/urban-survey
chown -R survey:survey /opt/urban-survey
cd /opt/urban-survey
sudo -u survey -H npm ci
sudo -u survey -H npm run setup
```

Skip account creation if `survey` already exists. Do not clone over an existing installation. Node.js must already be installed system-wide; the supplied service expects `/usr/bin/node`. Check `which node` and adjust `ExecStart` if needed. A Node installation under root's private version-manager directory is not suitable for the service account.

## 2. Install the PDF browser

```bash
cd /opt/urban-survey
node node_modules/playwright/cli.js install-deps chromium
sudo -u survey -H npm run pdf:install
```

Install the browser as `survey`, not root. The service sets `HOME=/home/survey`, so its browser cache must be available to that account. If the provider refuses the download, follow [PDF troubleshooting](pdf-troubleshooting.md).

## 3. Configure production settings

Edit `/opt/urban-survey/.env.local`. Keep the random `SESSION_SECRET` generated by setup and set:

```dotenv
ADMIN_USERNAME=your-admin-name
ADMIN_PASSWORD='your-long-private-password'
DATABASE_PATH=/opt/urban-survey/data/survey.sqlite
APP_ORIGIN=https://survey.example.com
COOKIE_SECURE=true
```

Do not leave the default administrator password on a public installation. Use the exact browser origin, including the port when it is not standard. Do not append a slash. For temporary HTTP testing, use an HTTP origin and `COOKIE_SECURE=false`, then switch both settings when HTTPS is enabled.

```bash
chmod 600 /opt/urban-survey/.env.local
chown survey:survey /opt/urban-survey/.env.local
sudo -u survey -H npm test
sudo -u survey -H npm run test:pdf
sudo -u survey -H npm run build
```

## 4. Start the service

```bash
cp deploy/urban-survey.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now urban-survey
systemctl status urban-survey --no-pager
```

The application listens on `127.0.0.1:3000`. Keep this port private and let Nginx handle public traffic. To inspect failures:

```bash
journalctl -u urban-survey -n 100 --no-pager
```

## 5. Configure Nginx and HTTPS

```bash
cp /opt/urban-survey/deploy/nginx.conf /etc/nginx/sites-available/urban-survey
nano /etc/nginx/sites-available/urban-survey
```

Replace `survey.example.com` in `server_name`. Create the following symlink only if it does not already exist:

```bash
ln -s /etc/nginx/sites-available/urban-survey /etc/nginx/sites-enabled/urban-survey
nginx -t
systemctl enable --now nginx
systemctl reload nginx
certbot --nginx -d survey.example.com
certbot renew --dry-run
```

The domain's DNS record must point to this server. When using Cloudflare, enable Full (strict) after a valid origin certificate is installed. Do not apply forced caching to `/admin*` or `/api/*`. Large combined PDFs can take longer to render; intermediary proxies may impose their own request timeout even with the supplied Nginx timeout.

## 6. Verify the installation

Open the public questionnaire, submit a clearly labeled test response, and sign in at `/admin`. Verify the record, summary statistics, individual PDF and combined PDF. Delete the test response when finished. A passing command-line PDF test does not confirm that the running service has loaded the same environment; restart the service after editing `.env.local`.

## Changing the administrator password

Edit `ADMIN_PASSWORD` in `.env.local` and run:

```bash
systemctl restart urban-survey
```

Changing a password does not revoke already issued sessions. To revoke them, also replace `SESSION_SECRET` with a new cryptographically random value before restarting. Do not share the environment file when asking for support.

## Updating an existing deployment

First create a backup and record the current Git commit. Keep `.env.local`, `data/` and `backups/` in place.

```bash
cd /opt/urban-survey
sudo -u survey -H npm run backup
sudo -u survey -H git rev-parse HEAD
systemctl stop urban-survey
sudo -u survey -H git pull --ff-only
sudo -u survey -H npm ci
sudo -u survey -H npm test
sudo -u survey -H npm run build
sudo -u survey -H npm run test:pdf
systemctl start urban-survey
```

Stop at a failed command and resolve it before continuing. If Playwright was updated, install its matching browser again or update your explicit browser path. If the update cannot be completed, restore the recorded source revision and reinstall/build it before restarting. Never overwrite a live database with an empty repository directory.

An installation originally copied from a ZIP is not a Git checkout. For its first migration, prepare a fresh checkout separately and follow the migration steps below; `git pull` will not work in the original ZIP directory.

## Moving to another server

1. Put the old installation into maintenance by stopping the service, then run `npm run backup` as `survey` from the project directory. Keep it stopped during the final transfer so no submissions are missed.
2. Set up the same source version and dependencies on the destination.
3. Keep the destination service stopped. Transfer the backup securely and place it at the destination `DATABASE_PATH`. Use a fresh database location. If replacing a database, archive its old SQLite, WAL and SHM files together while the service is stopped.
4. Set ownership to the destination service user. Configure `.env.local` with the new origin, credentials and a new session secret. Do not copy Windows `node_modules` to Linux.
5. Install or transfer Chromium and test PDFs. Build the application, configure HTTPS, start the service and verify record counts.
6. Change DNS and retire the old service after verification. Do not allow both copies to collect responses independently.

A SQLite backup contains participant records and a fallback session-signing key. Store and transfer it privately. See [data and reporting](data-and-reporting.md) for backup behavior.
